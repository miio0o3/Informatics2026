# IITの例：音楽アンサンブルにおける同期

## 概要

このプロジェクトでは、Integrated Information Theory（IIT：統合情報理論）に関連する簡単な例を示します。

ここでは、3人の演奏者 A, B, C からなる音楽アンサンブルを考えます。  
各演奏者のタイミングには、次の3つの状態があるとします。

- `E`：早い（early）
- `O`：拍に合っている（on beat）
- `L`：遅い（late）

この例では、「全体として同期しているアンサンブル」と、「各演奏者を独立に扱った場合」を比較します。

## アイデア

全体として同期しているアンサンブルでは、3人の演奏者は同じタイミングを共有していると考えます。

そのため、可能な未来の状態は次の3つだけです。

- `EEE`
- `OOO`
- `LLL`

それぞれの状態が起こる確率を `1/3` とします。

これは、全体のシステムが「演奏者たちが同期している」という関係を指定していると考えることができます。

一方で、アンサンブルを3人の独立した演奏者に分けて考えると、それぞれの演奏者は `E`, `O`, `L` のいずれかを確率 `1/3` でとるだけになります。  
その場合、`EOL` や `OLE` のように、演奏者ごとのタイミングがばらばらな状態も可能になります。

つまり、全体として存在していた「同期している」という関係が、独立な部分に分けることで失われます。

## IITとの関係

IITでは、システム全体の情報が、独立した部分の情報に単純に分解できない場合に、統合された情報があると考えます。

この例では、アンサンブル全体は「全員が同じタイミングで演奏する」という同期関係を持っています。  
しかし、各演奏者を独立に扱うと、その同期関係は表現できません。

そのため、全体として同期している場合の確率分布と、独立な演奏者に分割した場合の確率分布を比較することで、IITにおける integration の考え方を簡単に可視化しています。

なお、このプログラムは厳密なIITの量を計算するものではなく、講義で扱われた「分割すると失われる全体としての関係」という考え方を説明するための簡単な例です。

## 方法

このプログラムでは、次の2つの確率分布を比較します。

1. 全体として同期しているアンサンブルの確率分布
2. 各演奏者を独立に扱った場合の確率分布

この2つの違いを、KLダイバージェンスによって測ります。

`D_KL(p || q)`

ここで、`p` は全体として同期しているアンサンブルの確率分布、`q` は分割後の独立な演奏者の確率分布を表します。

## 実行方法

次のコマンドでPythonファイルを実行します。

`python iit_music.py`

## 出力

プログラムを実行すると、全体として同期しているアンサンブルと、独立に分割した演奏者の確率分布を比較する棒グラフが表示されます。

また、次の画像ファイルも保存されます。

`music_plot.png`

![音楽アンサンブルにおける同期の例](music_sync_plot.png)

グラフでは、全体のシステムでは `EEE`, `OOO`, `LLL` のみが起こるのに対して、分割後のシステムではすべての組み合わせが起こり得ることが示されています。

KLダイバージェンスの値は、アンサンブルを独立な演奏者に分けたときに、どれだけ全体としての関係が失われるかを表しています。
